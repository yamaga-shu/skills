# ドキュメント運用規約

AI エージェントがドキュメントとコード内コメントを書く際に従う規約。
人間の運用を縛るものではなく、AI に一貫した振る舞いをさせることを目的とする。

## 正本の表

**同じ事実を複数の場所に書かない。** 事実の種類ごとに正本を一つ決め、他の場所には書かないか、
「正本は◯◯」と参照だけを書く。

| 書くこと | 正本 | 既定の場所 |
| --- | --- | --- |
| 挙動・使い方 | README | 対象ディレクトリ |
| ファイルの役割（1 行）、開発コマンド、他文書へのポインタ | AGENTS.md | 対象ディレクトリ |
| 用語の定義 | 用語集 | ルートの `CONTEXT.md`。複数コンテキストではルートの `CONTEXT-MAP.md` が各コンテキストの `CONTEXT.md` を指す |
| ADR の条件を満たす設計判断の結論 | ADR | `docs/adr/`。複数コンテキストでは、コンテキスト固有の決定は各 `CONTEXT.md` と同じ階層の `docs/adr/` に置き、システム全体の決定はルートの `docs/adr/` に置く |
| それ以外の設計判断、検討の経緯・比較・選ばなかった案 | issue | 無ければ PR 本文またはコミットメッセージ |
| 特定の行にしか現れない制約 | その行のコメント | |
| 実装の現在の状態（「現状は stub」等） | そのコードの docstring | |

- 既定の場所を変えるリポジトリは、ルートの AGENTS.md に「ドキュメント規約」の節を置く。
  ```markdown
  ## ドキュメント規約
  - 用語集: `docs/glossary.md`
  - ADR: `doc/decisions/`
  ```
- **始める前にルートの AGENTS.md を読む。** 自動で読み込まれる保証はないので、明示的に読む。
  「ドキュメント規約」の節があれば、そこに書かれた項目だけ既定の場所を置き換える。
- この表と AGENTS.md の上書きが置き場所の正本である。他のスキルは既定の場所を例として使うだけで、
  置き場所の規則を書き直さない。
- まだ無い場所は、最初に必要になった時点で作る。
- 設計書（スペック）を一つの文書として置かず、表に従って README・ADR・用語集・issue に分ける。
- ADR を書くかどうかの判断と書式は domain-modeling スキルが正本である
  （ADR を書く前に Skill ツールで "domain-modeling" を読み込む）。
  複数コンテキストに用語集を分ける場合の構成も同スキルに従う。
- 参照の例: `pyproject.toml` の requires-python に「正本は Dockerfile の FROM」。

## AGENTS.md は短く保つ

AGENTS.md は常にコンテキストに載る。書くのは次の三つだけにする。
ディレクトリ・ファイル構成（1 行の役割付き）、開発コマンド（ビルド、テスト、lint など）、
「◯◯をする前に△△を読む」という他文書へのポインタ。
説明や規則の本文は正本に書き、AGENTS.md にはポインタだけを置く。
ルートの AGENTS.md には各ディレクトリの概要を 1 行だけ書き、詳細はそのディレクトリの AGENTS.md に譲る。

## コメント・docstring

コメントの役割は、コードの繰り返しではなく短縮である。書いてよいのは次の二つ。

- **読み取りに時間がかかることの要約** — 長い関数の処理のまとまりに付ける見出し、
  込み入ったロジックの要約。ただし、まず分割や命名で読み取り自体を速くできないかを
  検討し、それでも残る複雑さに書く。
- **消す・変えると壊れる値のガード** — その行だけを見ると不要・恣意的に見える設定に、
  理由を 1〜2 行で添える（例: compose の `init: true`、タイムアウトの具体値）。
  1〜2 行に収まらない経緯や比較は issue・PR・コミットメッセージに書く。

迷ったら「このコメントを消したら、読み手が同じ理解に達するまでの時間は延びるか、
または知らずに壊す危険が生まれるか」で判定する。どちらも No なら書かない。

- 冗長と分かったコメントは、理由の文だけ残す折衷をせず行ごと削除する。
- 識別子を改名したら、docstring・コメント・ドキュメント内の旧名も追随させる。
- コメントの言語はそのファイルの既存コメントに合わせる。無ければドキュメントの言語に合わせる。

## 文章の書き方

- 言語は既存ドキュメントに合わせる。無ければユーザーが使っている言語にする。
- 日本語は [references/japanese-writing.md](./references/japanese-writing.md) に従う。
  このファイルは自動では読み込まれないため、日本語のドキュメントを書く前、直す前に読むこと。
- 言語を問わず、同一主張の言い換え繰り返しを避け、見出しは内容を特定できる具体的な句にし、
  「重要なのは」「不可欠」「掘り下げる」、英語なら "It's important to note", "delve" のような
  中身のない LLM 的な型を使わない。

## セルフチェック

ドキュメントやコメントを書いたら、以下を自問する。

- 書いた事実の正本はどこか。正本の表に照らして、正本以外の場所に書いていないか
- AGENTS.md を読んだか。用語集や ADR の置き場所が上書きされているのに、既定の場所に書いていないか
- 消しても読み手の理解にかかる時間が延びず、壊す危険も生まれないコメントはないか
- 「現状は」「まだ」のような時間で腐る記述を、docstring 以外に書いていないか
