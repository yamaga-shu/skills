# AI エージェント用 issue 本文テンプレート

AI が issue を作成するときは、以下の構成に従って本文を組み立てる。
人間が issue を書く際にこの構成に従う必要はない。

各節の `<!-- -->` は記入の指針であり、本文には残さない。
該当しない節は節ごと削除してよい。逆に、必要なら節を足してよい。

冒頭にはリード文として、この issue で何を達成するのかを数行で述べる。見出しは付けない。

## 設計

<!--
構造や処理の流れを Mermaid の図で示す。GitHub は issue 本文の mermaid コードブロックをそのまま描画する。
扱う対象に応じて図の種類を選ぶ。

| 対象 | 図 |
| --- | --- |
| コンポーネントの構成、データの流れ | `flowchart` |
| 複数の登場人物をまたぐ処理の順序 | `sequenceDiagram` |
| テーブルとその関係 | `erDiagram` |
| 状態の遷移 | `stateDiagram-v2` |

mermaid のコードブロックとして、たとえば次のように書く。

    ```mermaid
    flowchart LR
        A[入力] --> B[処理] --> C[出力]
    ```

ディレクトリ構成のような木構造は図にせず、`text` のコードブロックにツリーで書く。

図に語らせすぎない。図から読み取れない判断の理由は、必ず文で補う。
図示するほどの構造がない issue ではこの節ごと削除する。
用語集（CONTEXT.md）があるリポジトリでは、ユーザーが `/domain-design` を呼ぶと、設計パターンを詰めたうえでこの節を用語集の言葉で描き直せる。
-->
