# 実装計画のテンプレート

plan-from-issue が issue のコメントとして投稿する計画の構成。
ユーザーに提示するときも同じ構成で書く。

各節の `<!-- -->` は記入の指針であり、本文には残さない。
該当しない節は節ごと削除してよい。逆に、必要なら節を足してよい。

issue の本文に書かれていること（決定、設計、完了条件）は書き写さず、参照する。

---

## 実装計画

<!-- この見出しは固定。実装者がコメントの中から計画を見つける目印にする。 -->

### ブランチ

<!--
git-convention に従ったブランチ名と、切る元。
元は既定ブランチか、続きから始める既存ブランチ。既存ブランチなら、既に入っているコミットを一行で述べる。
その issue を閉じる open な PR が既にあれば、その番号を書く。実装者は新しい PR を作らず、その PR を更新する。
-->

### コミット

<!--
順に並べる。番号、件名、変更する場所、なぜそう変えるか。
件名は git-convention のコミットメッセージの書式で書き、実装時にそのまま使う。
理由はコミット本文の下書きである。差分を読めば分かることは書かず、一段落に収める。
そのコミットで通すべきコマンド（テスト、lint）があれば添える。
-->

1. `refactor: <件名>`
   - 変更: `path/to/file` の関数 X を ...
   - 理由: ...
2. `feat: <件名>`
   - 変更: ...
   - 理由: ...
   - 確認: `npm test`

ここに書いたものは PR 本文の「検討したこと」に写す。
計画の構成に影響せず、実装中に決めればよいものは、推奨案だけを書く。
-->

| 論点 | 方針 | 理由 |
