# ドメインモデリング

設計しながら、プロジェクトのドメインモデルを能動的に構築し、研ぎ澄ます。これは _能動的な_ 規律である。用語に異議を唱え、エッジケースのシナリオを考案し、用語集と決定が固まった瞬間に書き留める。（語彙を借りるために `CONTEXT.md` を _読む_ だけならこのスキルではない。それはどのスキルでもできる一行の習慣である。このスキルはモデルを消費するときではなく、変えるときのためのものである。）

## 前提: doc-convention

用語集と ADR の置き場所、および「一つの事実は一箇所に」の原則は doc-convention スキルの「正本の表」に従う。まだ読んでいなければ、Skill ツールで "doc-convention" を読み込む。以下のファイル構成の例は、その表の既定の場所で書いている。

## ファイル構成

多くのリポジトリはコンテキストが一つである。

```
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-event-sourced-orders.md
│       └── 0002-postgres-for-write-model.md
└── src/
```

ルートに `CONTEXT-MAP.md` があれば、そのリポジトリは複数のコンテキストを持つ。マップが各コンテキストの場所を指す。

```
/
├── CONTEXT-MAP.md
├── docs/
│   └── adr/                          ← システム全体の決定
├── src/
│   ├── ordering/
│   │   ├── CONTEXT.md
│   │   └── docs/adr/                 ← このコンテキスト固有の決定
│   └── billing/
│       ├── CONTEXT.md
│       └── docs/adr/
```

ファイルは遅延して作る。書くことができたときにだけ作る。`CONTEXT.md` が無ければ、最初の用語が確定したときに作る。ADR の置き場所が無ければ、最初の ADR が必要になったときに作る。

## セッション中

### 用語集と照らして異議を唱える

ユーザーが `CONTEXT.md` の既存の言葉と食い違う用語を使ったら、その場で指摘する。「用語集では『キャンセル』を X と定義していますが、いま言っているのは Y のようです。どちらですか」

### 曖昧な言葉を鋭くする

ユーザーが曖昧な用語や多義的な用語を使ったら、正確な正式用語を提案する。「『アカウント』と言っていますが、Customer と User のどちらですか。この二つは別物です」

### 具体的なシナリオで議論する

ドメインの関係を議論しているときは、具体的なシナリオで負荷をかける。エッジケースを突くシナリオを考案し、概念同士の境界をユーザーに正確に言わせる。

### コードと突き合わせる

ユーザーが「こう動く」と述べたら、コードがそれと一致するか確認する。矛盾を見つけたら表に出す。「コードは Order 全体をキャンセルしていますが、いま部分キャンセルが可能だと言いました。どちらが正しいですか」

### CONTEXT.md をその場で更新する

用語が確定したら、その場で `CONTEXT.md` を更新する。まとめて後で書かず、起きた瞬間に捕まえる。書式は [CONTEXT-FORMAT.md](./CONTEXT-FORMAT.md) に従う。

`CONTEXT.md` には実装の詳細を一切書かない。`CONTEXT.md` をスペック、メモ帳、実装上の決定の置き場として扱わない。用語集であり、それ以外の何物でもない。設計判断の結論は ADR に、検討の経緯は issue に置く（doc-convention の正本の表を参照）。

### ADR は控えめに提案する

次の三つがすべて当てはまるときだけ、ADR の作成を提案する。

1. **覆しにくい**: 後で考えを変えるコストが無視できない
2. **文脈がないと驚く**: 将来の読み手が「なぜこうしたのか」と疑問に思う
3. **本物のトレードオフの結果**: 現実的な代替案があり、特定の理由でその一つを選んだ

一つでも欠けていれば ADR は書かない。簡単に覆せる決定なら、覆せばよいだけである。驚かない決定なら、誰も理由を疑問に思わない。現実的な代替案が無かったなら、「当然のことをした」以上に記録することはない。

書式と、条件を満たす決定の例は [ADR-FORMAT.md](./ADR-FORMAT.md) に従う。
